## 1. Завдання для попередньої підготовки

### 1.1 — Глосарій термінів (Dictionary)

| Термін | Визначення та призначення |
| :--- | :--- |
| **User account** | Обліковий запис, що забезпечує ідентифікацію та автентифікацію користувача в системі. |
| **Root user** | Обліковий запис суперкористувача (адміністратора), що володіє повним доступом до всіх ресурсів ОС. |
| **Privileges** | Права доступу, що визначають перелік дозволених операцій для конкретного суб'єкта. |
| **Group** | Логічне об'єднання облікових записів для спрощення управління колективними правами доступу. |
| **UID (User ID)** | Унікальний числовий ідентифікатор, що присвоюється кожному користувачу в системі. |
| **GID (Group ID)** | Унікальний числовий ідентифікатор, що присвоюється кожній групі в системі. |
| **System account** | Службовий обліковий запис, призначений для виконання системних процесів та сервісів. |
| **Authentication** | Процедура перевірки справжності заявленого ідентифікатора користувача. |
| **Authorization** | Процес надання користувачеві прав на доступ до певних ресурсів після автентифікації. |
| **Primary group** | Основна група користувача, що встановлюється за замовчуванням для створених ним об'єктів. |
| **Secondary group** | Додаткова група, членом якої є користувач для отримання розширених прав доступу. |

### 1.2 — Теоретичні відомості

#### 1.2.1 — Концепція UPG (User Private Group)

**User Private Group** — це схема організації прав доступу, за якої:
- Для кожного нового користувача автоматично створюється однойменна група.
- Дана група містить лише одного члена — самого користувача.
- Це дозволяє безпечно встановлювати права доступу на файли (наприклад, `rw-rw-r--`), не надаючи при цьому доступу іншим користувачам.

**Приклад структури:**

| Користувач | Приватна група (UPG) |
| :--- | :--- |
| Dmytro | Dmytro |

**Доцільність використання:**
1. **Ізоляція даних:** Забезпечення високого рівня конфіденційності особистих файлів.
2. **Гнучкість управління:** Спрощення процесу спільної роботи над проектами через додавання користувачів до групових директорій.
3. **Безпека:** Мінімізація ризику несанкціонованого доступу до даних у багатокористувацькому середовищі.

## 2. Інструментарій та методи виконання

У процесі виконання роботи було використано наступний набір системних утиліт:

| Утиліта | Функціональне призначення |
| :--- | :--- |
| `su` | Заміна поточного ідентифікатора користувача на інший (зазвичай суперкористувача). |
| `sudo` | Виконання окремих операцій із привілеями адміністратора. |
| `id` | Виведення інформації про UID, GID та групову приналежність користувача. |
| `exit` | Завершення поточного сеансу оболонки (shell). |
| `head` | Відображення початкової частини текстового файлу. |
| `grep` | Фільтрація текстових даних за заданим шаблоном. |
| `getent` | Отримання записів із системних баз даних (passwd, group тощо). |
| `who` / `w` | Моніторинг активних користувачів та їхньої поточної активності в системі. |
| `last` / `lastb` | Аналіз успішних та невдалих спроб автентифікації в системі. |
| `groupadd` | Створення нових груп користувачів (параметри: `-r` — системна, `-g` — GID). |
| `groupmod` | Модифікація параметрів існуючих груп (параметри: `-n` — назва, `-g` — GID). |
| `useradd` | Реєстрація нового користувача (параметри: `-m` — створення каталогу, `-G` — групи). |
| `passwd` | Встановлення або зміна пароля облікового запису. |
| `usermod` | Зміна конфігурації облікового запису (параметри: `-aG` — додавання до груп, `-L` — блокування). |
| `groupdel` | Видалення групи із системи. |
| `userdel` | Видалення облікового запису (параметр `-r` — видалення домашньої директорії). |

## Хід виконання роботи

### 1. Виведення інформації про поточного користувача
Для отримання детальної інформації про поточний обліковий запис використовуємо команди `id` (ідентифікатори) та `grep` (пошук у базі даних паролів).

```bash
# Перегляд UID, GID та груп
id

# Пошук запису про користувача у файлі /etc/passwd
grep $USER /etc/passwd
```

### 2. Моніторинг активності користувачів
Порівняння результатів команд `last`, `w` та `who`:
* **who**: виводить список користувачів, які зараз працюють у системі, та їхні термінали.
* **w**: надає розширену інформацію — хто в системі, час роботи (uptime), середнє навантаження та назви процесів, які вони виконують.
* **last**: відображає історію останніх входів у систему (включаючи завершені сесії та перезавантаження).

```bash
last
w
who
```

### 3. Керування групами користувачів
Створюємо три нові групи та перевіряємо їхні ідентифікатори (GID).

```bash
sudo groupadd super_admins
sudo groupadd noob_users
sudo groupadd good_students

# Перевірка створених груп
getent group super_admins noob_users good_students
```

### 4. Створення облікових записів
Створюємо трьох нових користувачів та встановлюємо для них паролі.

```bash
sudo useradd user_alpha && sudo passwd user_alpha
sudo useradd user_beta && sudo passwd user_beta
sudo useradd user_gamma && sudo passwd user_gamma
```

### 5. Розподіл користувачів за групами
Додаємо користувачів до створених груп згідно з технічним завданням.

```bash
# Додавання до super_admins та good_students
sudo usermod -aG super_admins,good_students user_alpha

# Додавання до всіх трьох груп (user_beta є спільним для перших двох)
sudo usermod -aG super_admins,noob_users,good_students user_beta

# Додавання до noob_users та good_students
sudo usermod -aG noob_users,good_students user_gamma
```

### 6. Видалення та очищення системи
Послідовно видаляємо створені облікові записи та групи для повернення системи до початкового стану.

```bash
# Видалення користувачів
sudo userdel user_alpha
sudo userdel user_beta
sudo userdel user_gamma

# Видалення груп
sudo groupdel super_admins
sudo groupdel noob_users
sudo groupdel good_students
```

## Контрольні запитання

1. **Чому в конфігураційних файлах паролі не зберігаються в явному вигляді?**
   Задля безпеки. У файлі `/etc/shadow` зберігаються лише хеш-суми паролів. Це унеможливлює компрометацію пароля навіть у разі отримання доступу до файлу.
2. **Чому не рекомендується виконувати повсякденні операції під root?**
   Обліковий запис root має необмежені права. Будь-яка помилка в команді або вразливість у запущеному ПЗ може призвести до незворотного пошкодження всієї системи.
3. **У чому відмінність між su та sudo?**
   `su` (substitute user) повністю перемикає сесію на іншого користувача (вимагає пароль цільового користувача/root). `sudo` дозволяє виконати конкретну команду з привілеями адміністратора (вимагає пароль поточного користувача).
4. **Чому домашній каталог root (/root) не розміщено в /home?**
   Це гарантує можливість входу адміністратора в систему для відновлення, навіть якщо розділ `/home` не вдалося змонтувати через помилки диска.
5. **Для чого використовується команда getent?**
   Вона дозволяє отримувати записи з адміністративних баз даних (passwd, group тощо) незалежно від того, чи зберігаються вони локально, чи в мережевих службах (наприклад, LDAP).
6. **Як змінити пароль користувача?**
   Використовується команда `passwd [ім'я_користувача]`.
7. **Як видалити групи і що станеться з інформацією про них?**
   Командою `groupdel`. Назва групи зникне з `/etc/group`, але файли, що їй належали, збережуть старий числовий ідентифікатор GID.
8. **Призначення команди chage?**
   Керування термінами дії паролів: встановлення дати завершення дії, періоду обов'язкової зміни та налаштування попереджень.
9. **Найбільш використовувані параметри usermod?**
   `-aG` (додавання до додаткових груп), `-l` (зміна імені логіна), `-L` (блокування облікового запису).
