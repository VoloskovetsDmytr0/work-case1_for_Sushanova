## 1. Завдання для попередньої підготовки

### 1.1 — Термінологічний словник

| Термін | Пояснення |
| :--- | :--- |
| File ownership (Приналежність файлу) | Принцип, за яким будь-який об'єкт у файловій системі закріплений за конкретним користувачем та групою. |
| User owner (Власник-користувач) | Безпосередній творець або призначений власник файлу. |
| Group owner (Власник-група) | Група користувачів, якій належить даний файл. |
| Permissions (Дозволи) | Набір атрибутів, що регламентують рівень доступу до об'єкта (перегляд, зміна, виконання). |
| Read / r (Читання) | Атрибут, що дозволяє переглядати вміст файлу або список файлів у каталозі. |
| Write / w (Запис) | Атрибут, що дає змогу модифікувати файл або створювати/видаляти об'єкти в директорії. |
| Execute / x (Виконання) | Атрибут, необхідний для запуску файлу як програми (або входу до директорії). |
| Default permissions (Стандартні права) | Базовий набір прав, який автоматично застосовується під час створення нового об'єкта. |
| Hidden file (Прихований файл) | Об'єкт, назва якого починається з символу крапки (`.`). |
| Primary group (Основна група) | Головна група, яка присвоюється користувачу за замовчуванням при створенні облікового запису. |
| Supplementary groups (Додаткові групи) | Суміжні групи, до яких може бути включений користувач для розширення його прав. |
| Binary file (Бінарний файл) | Скомпільований файл, готовий до виконання процесором. |
| setuid | Спеціальний біт доступу. Дозволяє запускати програму з привілеями користувача-власника цього файлу. |
| setgid | Спеціальний біт доступу. Дозволяє програмі виконуватись з правами групи-власника (або успадковувати групу для нових файлів у каталозі). |
| Sticky bit | Атрибут безпеки для спільних каталогів, що забороняє користувачам видаляти чужі файли. |

### 1.2 Питання

#### Для чого потрібна команда id?

Ця утиліта виводить поточну ідентифікаційну інформацію про користувача, зокрема його унікальний номер (UID), номер основної групи (GID) та перелік усіх додаткових груп, до яких він належить.

#### Як перевірити права доступу власника файлу?

Для цього використовується команда розширеного лістингу:
```bash
ls -l
```
У результаті виводиться рядок атрибутів (наприклад, `-rwxrw-r--`). Перші три символи (після індикатора типу файлу) відповідають саме за дозволи власника (у даному випадку `rwx`).

#### Як змінити групу, якій належить файл?

Існує два основні способи:
Використовуючи утиліту `chgrp`:
```bash
chgrp нова_група ім'я_файлу
```
Або через команду `chown`:
```bash
chown :нова_група ім'я_файлу
```

#### Як дізнатися тип файлу через термінал?

Тип можна визначити за допомогою команди `ls -l`. Перший символ у рядку прав вказує на тип об'єкта:
* `-` (звичайний файл)
* `d` (директорія)
* `l` (символьне посилання)

Більш детальну інформацію про вміст та тип дає утиліта:
```bash
file ім'я_файлу
```

#### Що таке Setuid та Setgid?

* **Setuid (SUID):** Надає можливість звичайному юзеру тимчасово отримати права власника файлу під час виконання програми. Класичний приклад — утиліта `passwd`, яка дозволяє змінювати свій пароль, вносячи зміни у системні файли, до яких є доступ лише у root.
* **Setgid (SGID):** Для файлів працює аналогічно SUID, але надає права групи. Якщо атрибут застосовано до директорії, усі створені в ній нові файли автоматично успадковуватимуть групу цієї директорії, що дуже зручно для організації спільної роботи.

#### Поняття Sticky Bit

Це додатковий рівень захисту для спільних директорій. Якщо цей біт активовано (відображається як `t` у кінці прав, наприклад `drwxrwxrwt`), то видалити чи перейменувати файл у такій папці зможе лише його автор, власник самої папки або суперкористувач. Найвідоміший приклад — системна папка `/tmp`.

```bash
sudo useradd -m user3

# Задання паролів (за необхідності)
sudo passwd user1
sudo passwd user2
sudo passwd user3

# Створення групи та додавання користувачів
sudo groupadd labgroup
sudo usermod -aG labgroup user1
sudo usermod -aG labgroup user2

# Перевірка
id user1
id user2
id user3
```

## 2.2 Налаштування прав доступу для файлу (скрипта)

**Завдання:** Створити файл-скрипт. Власнику — читання, запис, виконання (rwx). Групі — читання, виконання (r-x). Іншим — заборонити доступ (---).

**Виконані команди:**
```bash
# Створення файлу та запис найпростішого скрипта
echo '#!/bin/bash' > test_script.sh
echo 'echo "Hello, Linux!"' >> test_script.sh

# Налаштування власника та групи (якщо створювали під root, змінюємо на user1)
sudo chown user1:labgroup test_script.sh

# Зміна прав доступу (7 = rwx для власника, 5 = r-x для групи, 0 = --- для інших)
sudo chmod 750 test_script.sh

# Перевірка прав
ls -l test_script.sh
```

## 2.3 Налаштування прав доступу для директорій

**Завдання:** Створити три директорії з різними рівнями доступу.

**Виконані команди:**
```bash
# Створення директорій
mkdir dir_all dir_owner dir_group_readonly

# 1. Доступна для всіх користувачів (повні права)

chmod 750 dir_group_readonly

# Перевірка
ls -ld dir_*
```

## 2.4 Дослідження команди chmod у числовому режимі

**Завдання:** Створити `emptyfile`, обнулити права. Перевірити роботу `chmod 4` та `chmod 44`. Зробити висновки.

**Виконані дії:**
```bash
touch emptyfile
chmod 000 emptyfile
ls -l emptyfile

chmod 4 emptyfile
ls -l emptyfile

chmod 44 emptyfile
ls -l emptyfile
```

<a href="https://ibb.co/hJH8QDJf"><img src="https://i.ibb.co/67bs9g7B/image.png" alt="image" border="0"></a>

**Пояснення (відповідь на запитання):**
Коли ми передаємо команді `chmod` числове значення, що складається менш ніж з трьох цифр, вона автоматично доповнює його нулями зліва. 
* Команда `chmod 4 emptyfile` інтерпретується як `chmod 004`. Це означає, що право на читання (`r = 4`) надається лише категорії "Інші" (Others). Права власника та групи залишаються `0`.
* Команда `chmod 44 emptyfile` інтерпретується як `chmod 044`. Це надає право на читання групі та іншим користувачам, залишаючи права власника нульовими.
* **Висновок:** `chmod` зчитує числове значення справа наліво (спочатку Інші, потім Група, потім Власник).

## 2.5 Створення спеціального каталогу (SGID + Sticky Bit)

**Завдання:** Створити каталог, де всі файли автоматично належатимуть групі, і видалити їх зможе лише той, хто їх створив.

**Виконані команди:**
```bash
mkdir shared_secure_dir
# Змінюємо групу каталогу на нашу
sudo chgrp labgroup shared_secure_dir

# Встановлюємо права: 
# 3 - це комбінація Sticky Bit (1) та SetGID (2) = 1+2=3
# 777 - повні права для всіх (щоб юзери могли створювати там файли)
sudo chmod 3777 shared_secure_dir

# Перевірка (має бути drwxrwsrwt)
ls -ld shared_secure_dir
```

### Відповіді на контрольні запитання

**1. Наведіть приклади зміни прав доступу символічним методом (Symbolic Method)?**
Символічний метод використовує літери для позначення категорій користувачів (`u` — власник, `g` — група, `o` — інші, `a` — всі), операцій (`+` — додати, `-` — забрати, `=` — встановити точно) та самих прав (`r`, `w`, `x`).
* `chmod u+x script.sh` — додає право на виконання для власника.
* `chmod g-w file.txt` — забирає право на запис (редагування) у групи.
* `chmod o=r config.conf` — встановлює для всіх інших виключно право на читання (всі інші права скидаються).
* `chmod a+r text.txt` — дозволяє читання абсолютно всім користувачам.

**2. Наведіть приклади зміни прав доступу числовим методом (numeric method, octal method)?**
Числовий (вісімковий) метод базується на сумі числових значень прав: `r = 4`, `w = 2`, `x = 1`. Три цифри підряд визначають права для власника, групи та інших відповідно.
* `chmod 755 app` — (7=4+2+1) власник має повні права (rwx), (5=4+1) група та інші можуть лише читати і виконувати (r-x). Типово для скриптів та директорій.
* `chmod 644 document.txt` — (6=4+2) власник може читати і писати (rw-), (4) група та інші — тільки читати (r--). Типово для звичайних файлів.
* `chmod 700 private_dir` — повний доступ (rwx) лише для власника, для інших доступ повністю закрито (0).

**3. Яке призначення команди umask?**
Команда `umask` (user file-creation mode mask) визначає набір прав доступу, які будуть автоматично **відніматися** (скидатися) від базових прав під час створення нових файлів та директорій. Базові права для директорій — `777`, для файлів — `666`. Якщо `umask` дорівнює `022`, то нові директорії отримають права `755` (777 - 022), а нові файли — `644` (666 - 022).

**4. Порівняйте жорсткі та символічні посилання?**
* **Жорстке посилання (Hard link):** Вказує на той самий унікальний індексний дескриптор (`inode`) на диску, що й оригінальний файл. По суті, це просто ще одне ім'я для тих самих даних. Їх не можна створювати для директорій та розміщувати на різних файлових системах (розділах).
* **Символічне посилання (Symlink / Soft link):** Це окремий маленький файл зі своїм `inode`, який містить лише текстовий шлях до оригінального файлу (аналог "ярлика" у Windows). Може вказувати на директорії, інші диски та навіть на неіснуючі файли.

**5. *Чи можна виконати файл, для якого є права на виконання, але не встановлені права на читання (--x)? Поясніть.**
Так, можна. Якщо для файлу встановлено лише право на виконання (`--x`), ви можете його запустити (наприклад, через `./script.sh`), за умови, що знаєте точний шлях до нього. Однак ви не зможете прочитати його вихідний код (наприклад, командою `cat` або відкривши в текстовому редакторі) чи скопіювати його.

**6. *Якщо ми змінюємо права доступу та дозволи в поточній сесії чи будуть вони збережені в наступній?**
Так, будуть. Зміни, зроблені командами `chmod`, `chown` або `chgrp`, записуються безпосередньо в метадані файлової системи на жорсткому диску. Вони є постійними і зберігаються після завершення сесії, перезапуску термінала чи перезавантаження комп'ютера.

**7. *Чи є якийсь шаблон, яким система користується щодо прав та доступів при створенні нових файлів. Як можна змінити права дозволу за замовчуванням?**
Так, цим шаблоном є згадана раніше маска `umask`. Щоб змінити права за замовчуванням у поточній сесії термінала, достатньо ввести команду з новим значенням, наприклад: `umask 002`. Щоб зробити цю зміну постійною для вашого користувача, цей рядок потрібно додати у конфігураційний файл оболонки (наприклад, `~/.bashrc` або `~/.profile`).

**8. *Яким чином можна створити жорстке посилання? В яких ситуаціях їх доцільно використовувати?**
Створюється командою: `ln файл_оригінал жорстке_посилання`.
Доцільно використовувати: для забезпечення цілісності важливих даних (файл не зникне з диска, поки не видалять усі його жорсткі посилання), для економії місця на диску (декілька імен вказують на один блок даних), або для створення надійних бекапів за допомогою утиліт типу `rsync`.

**9. *Яким чином можна створити символічне посилання? В яких ситуаціях їх доцільно використовувати?**
Створюється командою: `ln -s /шлях/до/оригіналу символічне_посилання`.
Доцільно використовувати: для створення зручних коротких "ярликів" до файлів або директорій, що заховані глибоко у файловій системі; для збереження сумісності (коли програма шукає конфіг за старим шляхом, а ви посиланням перенаправляєте її на новий); для посилань між різними фізичними дисками.

**10. **Уявіть, що програмі потрібно створити одноразовий тимчасовий файл, який більше ніколи не знадобиться після закриття програми. Який правильний каталог для створення цього файлу?**
Правильним вибором буде каталог `/tmp`. Файли в цій директорії призначені саме для короткострокового зберігання під час роботи програм, і вміст цього каталогу зазвичай автоматично очищується операційною системою під час кожного перезавантаження комп'ютера.

**11. **Є файл оригінал та для нього створено два посилання - символічне та жорстке. Що відбудеться з іншими файлами, якщо видалити:**
* **файл оригінал:** Символічне посилання "зламається" (стане битим/dangling), оскільки шлях, на який воно вказує, більше не існує. Жорстке посилання працюватиме як і раніше, а дані файлу залишаться неушкодженими на диску.
* **символічне посилання:** Зникне лише сам "ярлик". Оригінальний файл та жорстке посилання залишаться без змін і працюватимуть коректно.
* **жорстке посилання:** Зникне лише це конкретне ім'я файлу. Оригінальний файл та символічне посилання (яке вказує на ім'я оригіналу) залишаться без змін. Дані на диску видаляються лише тоді, коли видаляється останнє жорстке посилання.
