## 1. Завдання для попередньої підготовки

### 1.1 — Термінологічний словник

| Термін | Пояснення |
| :--- | :--- |
| File ownership (Приналежність файлу) | Принцип, за яким будь-який об'єкт у файловій системі закріплений за конкретним користувачем та групою. |
| User owner (Власник-користувач) | Безпосередній творець або призначений власник файлу. |
| Group owner (Власник-група) | Група користувачів, якій належить даний файл. |
| Permissions (Дозволи) | Набір атрибутів, що регламентують рівень доступу до об'єкта (перегляд, зміна, виконання). |
| Read / r (Читання) | Атрибут, що дозволяє переглядати вміст файлу або список файлів у каталозі. |
| Write / w (Запис) | Атрибут, що дає змогу модифікувати файл або створювати/видаляти об'єкти в директорії. |
| Execute / x (Виконання) | Атрибут, необхідний для запуску файлу як програми (або входу до директорії). |
| Default permissions (Стандартні права) | Базовий набір прав, який автоматично застосовується під час створення нового об'єкта. |
| Hidden file (Прихований файл) | Об'єкт, назва якого починається з символу крапки (`.`). |
| Primary group (Основна група) | Головна група, яка присвоюється користувачу за замовчуванням при створенні облікового запису. |
| Supplementary groups (Додаткові групи) | Суміжні групи, до яких може бути включений користувач для розширення його прав. |
| Binary file (Бінарний файл) | Скомпільований файл, готовий до виконання процесором. |
| setuid | Спеціальний біт доступу. Дозволяє запускати програму з привілеями користувача-власника цього файлу. |
| setgid | Спеціальний біт доступу. Дозволяє програмі виконуватись з правами групи-власника (або успадковувати групу для нових файлів у каталозі). |
| Sticky bit | Атрибут безпеки для спільних каталогів, що забороняє користувачам видаляти чужі файли. |

### 1.2 Питання

#### Для чого потрібна команда id?

Ця утиліта виводить поточну ідентифікаційну інформацію про користувача, зокрема його унікальний номер (UID), номер основної групи (GID) та перелік усіх додаткових груп, до яких він належить.

#### Як перевірити права доступу власника файлу?

Для цього використовується команда розширеного лістингу:
```bash
ls -l
```
У результаті виводиться рядок атрибутів (наприклад, `-rwxrw-r--`). Перші три символи (після індикатора типу файлу) відповідають саме за дозволи власника (у даному випадку `rwx`).

#### Як змінити групу, якій належить файл?

Існує два основні способи:
Використовуючи утиліту `chgrp`:
```bash
chgrp нова_група ім'я_файлу
```
Або через команду `chown`:
```bash
chown :нова_група ім'я_файлу
```

#### Як дізнатися тип файлу через термінал?

Тип можна визначити за допомогою команди `ls -l`. Перший символ у рядку прав вказує на тип об'єкта:
* `-` (звичайний файл)
* `d` (директорія)
* `l` (символьне посилання)

Більш детальну інформацію про вміст та тип дає утиліта:
```bash
file ім'я_файлу
```

#### Що таке Setuid та Setgid?

* **Setuid (SUID):** Надає можливість звичайному юзеру тимчасово отримати права власника файлу під час виконання програми. Класичний приклад — утиліта `passwd`, яка дозволяє змінювати свій пароль, вносячи зміни у системні файли, до яких є доступ лише у root.
* **Setgid (SGID):** Для файлів працює аналогічно SUID, але надає права групи. Якщо атрибут застосовано до директорії, усі створені в ній нові файли автоматично успадковуватимуть групу цієї директорії, що дуже зручно для організації спільної роботи.

#### Поняття Sticky Bit

Це додатковий рівень захисту для спільних директорій. Якщо цей біт активовано (відображається як `t` у кінці прав, наприклад `drwxrwxrwt`), то видалити чи перейменувати файл у такій папці зможе лише його автор, власник самої папки або суперкористувач. Найвідоміший приклад — системна папка `/tmp`.

### 2.1 — Огляд основних утиліт керування правами

| Команда | Опис та застосування |
| :--- | :--- |
| `chmod` | Утиліта для зміни дозволів. Наприклад, `a+x` робить файл виконуваним для всіх, `g-w` забороняє групі вносити зміни, `go+r` дає доступ на читання групі та решті, `o=rwx` встановлює повний доступ для інших юзерів. |
| `chown` | Змінює поточного власника (та за потреби групу) файлового об'єкта. |
| `chgrp -R` | Задає нову групу для об'єкта. Ключ `-R` забезпечує рекурсивне застосування команди до всіх вкладених файлів і тек. |
| `ls -ladi` | Вичерпна інформація про об'єкти. `-l` активує табличний формат, `-a` показує приховані елементи, `-d` виводить дані самої директорії (не розкриваючи її вміст), а `-i` додає колонку з індексним дескриптором (inode). |
| `stat` | Утиліта для отримання максимально детальних метаданих про файл. |
| `passwd` | Програма для генерації або оновлення пароля облікового запису. |
| `wall` | Засіб для розсилки текстових сповіщень на екрани всіх залогінених користувачів. |
| `rm` | Видалення об'єктів файлової системи. |
| `ln -s` | Створює "м'яке" (символьне) посилання на цільовий файл або теку. |

## Відповіді на контрольні запитання

### 1. Як змінити права доступу за допомогою символьного синтаксису?
Символьний метод базується на використанні літер. Наприклад, `chmod u+x script.sh` надасть власнику право запускати файл, `chmod g-w file.txt` відкличе право на редагування у групи, а `chmod o=r doc.pdf` жорстко встановить для категорії "інші" виключно можливість читання.

### 2. Як змінити права доступу у числовому (вісімковому) форматі?
Тут застосовуються тризначні комбінації. Значення `chmod 755 app` забезпечить власнику повні права (7 = 4+2+1, тобто r+w+x), а групі та решті — читання та запуск (5 = 4+1, тобто r+x). Інший приклад: `chmod 644 text.txt` дасть власнику r/w, а решті лише r.

### 3. Для чого потрібна команда umask?
Утиліта `umask` встановлює маску відсікання прав, яка застосовується до базових дозволів під час генерації нових об'єктів (файлів чи директорій), таким чином формуючи права за замовчуванням.

### 4. У чому різниця між жорсткими (hard) та символьними (symlink) посиланнями?
Жорстке посилання — це прямий вказівник на той самий `inode` на жорсткому диску, тобто просто альтернативне ім'я для тих самих даних. Їх не можна створювати для директорій або лінкувати файли між різними розділами. Символьне посилання діє як "ярлик" у Windows — це звичайний текстовий файл, що містить маршрут до оригінального файлу. Воно працює з директоріями і підтримує крос-розділові зв'язки.

### 5. Чи можливо виконати скрипт, якщо є право `x`, але відсутнє `r`?
Так. Якщо файл має лише атрибут на виконання (`--x`), його можна запустити (за умови, що ви знаєте точний шлях і назву). Однак ви не зможете вивести його вміст на екран через `cat` або скопіювати.

### 6. Чи зберігаються налаштовані права доступу після перезавантаження системи?
Так, зміни прав (виконані через `chmod` або `chown`) записуються безпосередньо у метадані файлової системи і є постійними.

### 7. Як система визначає дозволи для нових файлів і як це змінити?
Операційна система застосовує стандартну маску (`umask`). Щоб її модифікувати, потрібно викликати відповідну команду з новим значенням, наприклад `umask 0022`. Це змінить поведінку створення файлів для поточної сесії.

### 8. Як зробити жорстке посилання і коли це має сенс?
Команда: `ln джерело.txt лінк.txt`. Це корисно для створення локальних бекапів або організації доступу до одного файлу з різних директорій без ризику втратити дані при випадковому видаленні одного з імен (дані існують, поки є хоч один жорсткий лінк).

### 9. Як створити символьне посилання і навіщо воно потрібне?
Команда: `ln -s /шлях/джерело.txt ярлик.txt`. Використовується найчастіше для зручної навігації, створення ярликів до часто використовуваних конфігів або для вказівників на цілі директорії.

### 10. Де найкраще створювати тимчасові файли, які не будуть потрібні після завершення роботи?
Оптимальними локаціями для таких об'єктів є системні директорії `/tmp` або `/var/tmp`.

### 11. Що станеться, якщо видалити різні типи посилань?

| Видалений об'єкт | Наслідки |
| :--- | :--- |
| **Оригінал** | Сімлінк "зламається" (стане битим), оскільки шлях більше не існує. Жорстке посилання продовжуватиме працювати коректно, бо самі блоки даних на диску не видалені. |
| **Символьне посилання** | Буде видалено лише ярлик. Ані оригінал, ані інші файли не постраждають. |
| **Жорстке посилання** | Видалиться лише одне з імен файлу. Вміст залишатиметься на носії доти, доки не буде видалено останній файл, що вказує на цей `inode`. |
