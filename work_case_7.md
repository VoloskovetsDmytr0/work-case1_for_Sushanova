**Словник термінів**

* **Планувальник завдань (Task Scheduler)** — системний компонент або служба, що забезпечує автоматичний запуск програм, скриптів чи команд у заздалегідь визначений час або при настанні певних системних подій.
* **Cron** — класичний демон (фонова служба) в Unix-подібних операційних системах (зокрема Linux), призначений для регулярного виконання завдань за розкладом.
* **crontab (cron table)** — текстовий файл, у якому зберігається розклад і команди для виконання демоном Cron. Також це однойменна команда (`crontab -e`) для редагування цього файлу користувачем.
* **Демон (Daemon)** — комп'ютерна програма в Unix-системах, яка запускається самостійно і працює у фоновому режимі, не вимагаючи прямої взаємодії з користувачем.
* **systemd timers** — сучасна альтернатива Cron у дистрибутивах Linux на базі системи ініціалізації `systemd`. Використовує юніт-файли (`.timer` та `.service`) для точного планування завдань.
* **Anacron** — утиліта-планувальник для систем, які не працюють цілодобово ввімкненими (наприклад, ноутбуки). Забезпечує виконання завдань, пропущених через вимкнення машини, після її наступного запуску.
* **at** — утиліта командного рядка в Linux для одноразового виконання команди або скрипта у заданий час у майбутньому.
* **CLI (Command Line Interface)** — інтерфейс командного рядка, що дозволяє користувачу взаємодіяти з операційною системою за допомогою введення текстових команд.
* **GUI (Graphical User Interface)** — графічний інтерфейс користувача, де взаємодія з системою відбувається через візуальні елементи (вікна, кнопки, меню), як у Windows Task Scheduler.
* **systemctl** — основна утиліта командного рядка для контролю системи ініціалізації `systemd` та управління службами (включаючи запуск, зупинку та перевірку статусу таймерів). 
* **tar** — стандартна утиліта в Linux для створення та розпакування архівів (часто використовується в скриптах для резервного копіювання).

## 1. Теоретична частина: Планування задач в ОС

### Основні функції планувальника завдань
Планувальник завдань в будь-якій ОС — це системний компонент, який відповідає за автоматичне виконання скриптів, програм або команд у заданий час або при виникненні певних подій. Його основні функції:
* **Автоматизація рутини:** виконання регулярних завдань (резервне копіювання, очищення кешу, оновлення системи) без участі користувача.
* **Оптимізація ресурсів:** запуск важких фонових процесів у години найменшого навантаження на систему (наприклад, вночі).
* **Реакція на події:** виконання дій при завантаженні системи, вході користувача або зміні стану обладнання.

### Порівняння планувальників: Windows Task Scheduler vs Linux (Cron)
* **Windows Task Scheduler:** Має зручний графічний інтерфейс (GUI). Дозволяє створювати складні тригери (наприклад, запуск при розблокуванні робочої станції, при підключенні до певної мережі або при появі певного ID події в системному журналі). Тісно інтегрований з Active Directory.
* **Linux Cron:** Класичний інструмент командного рядка. Базується на текстових конфігураційних файлах (crontab). Дуже легкий, надійний і гнучкий, але не має вбудованої підтримки складних подій (наприклад, "при підключенні до Wi-Fi"), орієнтуючись переважно на часові інтервали.

### Основні принципи роботи з Cron в ОС Linux
**Cron** — це демон (фонова служба), який щохвилини перевіряє таблиці розкладу (`crontab`) і виконує задані команди.
* **Налаштування:** Здійснюється через редагування файлу розкладу поточного користувача командою `crontab -e`.
* **Синтаксис:** Запис складається з 5 полів часу та команди: 
    `[хвилини(0-59)] [години(0-23)] [день_місяця(1-31)] [місяць(1-12)] [день_тижня(0-7)] [команда]`

### Альтернативи Cron в Linux
1.  **Systemd Timers:** Сучасний стандарт для Ubuntu та інших дистрибутивів з systemd. Набагато потужніший за Cron: вміє логувати результати через `journalctl`, керувати залежностями (запускати задачу тільки якщо піднята мережа) і має захист від накладання паралельних виконань.
2.  **Anacron:** Доповнення до Cron для систем, які не працюють цілодобово (наприклад, ноутбуки). Якщо комп'ютер був вимкнений під час запланованого завдання, Anacron виконає його після увімкнення.
3.  **At:** Утиліта для планування разових завдань. Якщо задачу треба виконати лише один раз (наприклад, "перезавантажити сервер о 3-й ночі"), використовують `at`, а не Cron.

## 2. Практична робота з планувальником Cron

Для демонстрації роботи було відкрито файл розкладу командою `crontab -e` та додано наступні правила.

*[Місце для скріншоту: Відкритий термінал з виконаною командою crontab -e та доданими правилами]*

**2.1. Виконання задачі в чітко визначений час (о 08:30)**
Щоденне створення резервної копії каталогу з документами о 8:30 ранку:
```bash
30 8 * * * tar -czf /home/user/backup_$(date +\%F).tar.gz /home/user/Documents
```

**2.2. Виконання однієї й тієї ж задачі двічі в день**
Очищення тимчасової папки о 08:00 та о 20:00 щодня:
```bash
0 8,20 * * * rm -rf /home/user/tmp_files/*
```

**2.3. Виконання задачі тільки в будні у чітко визначений проміжок часу**
Запуск скрипта перевірки доступності мережевого вузла щогодини з 8:00 до 18:00 з понеділка по п'ятницю:
```bash
0 8-18 * * 1-5 /home/user/scripts/ping_check.sh
```

**2.4. Виконання задач з використанням спеціальних макросів**
Cron підтримує спеціальні рядки для спрощення синтаксису:
```bash
# Раз у рік (1 січня) - архівування старих логів
@yearly /home/user/scripts/archive_logs.sh

# Раз у місяць (1 числа) - оновлення пакетів
@monthly sudo apt update && sudo apt upgrade -y

# Раз у день (опівночі) - генерація звіту
@daily /home/user/scripts/daily_report.sh

# Щогодини - синхронізація часу
@hourly ntpdate pool.ntp.org

# При вмиканні (після перезавантаження) - запуск власного фонового додатку
@reboot /home/user/scripts/startup_app.sh
```

*[Місце для скріншоту: Вивід команди `crontab -l`, яка показує збережений список завдань]*

## 3. Робота з альтернативним планувальником (Systemd Timers)

В якості сучасної та потужної альтернативи Cron в Ubuntu було обрано **systemd timers**. Цей інструмент вбудований в систему за замовчуванням і є індустріальним стандартом.

**Методика налаштування задачі (на прикладі щоденного бекапу о 8:30):**

1. Створено service-файл, який описує, *що* саме треба зробити.
Шлях: `~/.config/systemd/user/mybackup.service`
```ini
[Unit]
Description=My Backup Task

[Service]
Type=oneshot
ExecStart=/bin/tar -czf /home/user/backup.tar.gz /home/user/Documents
```

2. Створено timer-файл, який описує, *коли* це треба зробити.
Шлях: `~/.config/systemd/user/mybackup.timer`
```ini
[Unit]
Description=Run backup at 8:30 AM daily

[Timer]
OnCalendar=*-*-* 08:30:00
Persistent=true

[Install]
WantedBy=timers.target
```
*(Параметр `Persistent=true` працює як anacron — якщо віртуальна машина була вимкнена о 8:30, завдання виконається одразу після її увімкнення).*

3. Активація та запуск таймера:
```bash
systemctl --user daemon-reload
systemctl --user enable --now mybackup.timer
```

4. Перевірка статусу запланованих завдань:
```bash
systemctl --user list-timers
```

*[Місце для скріншоту: Термінал з виводом команди `systemctl --user list-timers`, де видно доданий mybackup.timer і час його наступного запуску]*

## Висновки / Conclusions

**Висновки:** В ході виконання роботи було досліджено механізми планування завдань в операційних системах. Встановлено, що хоча Windows Task Scheduler надає ширші можливості відслідковування системних подій через зручний графічний інтерфейс, Linux-утиліта Cron є надзвичайно надійним і гнучким інструментом для виконання задач за розкладом на серверах. Практичне застосування Cron дозволило успішно налаштувати періодичне виконання команд у різні проміжки часу: конкретні години, робочі дні та при завантаженні системи. Також було розглянуто `systemd timers` як більш сучасну, безпечну та логічну альтернативу стандартному Cron в середовищі Ubuntu, що дозволяє детальніше контролювати стан виконання фонових процесів.

**Conclusions:** During the practical work, task scheduling mechanisms in operating systems were investigated. It was established that while Windows Task Scheduler provides broader event-tracking capabilities through a user-friendly GUI, the Linux Cron utility is an extremely reliable and flexible tool for executing scheduled tasks on servers. The practical application of Cron allowed for the successful configuration of periodic command execution at various time intervals: specific hours, workdays, and upon system boot. Furthermore, `systemd timers` were examined as a more modern, secure, and logical alternative to standard Cron in the Ubuntu environment, offering granular control over the execution state of background processes.
