## 1. Теоретичні відомості

### Основні функції планувальника завдань в ОС
Планувальник завдань (Task Scheduler) — це системний компонент, який забезпечує автоматичне виконання програм, скриптів або команд у визначений час або при настанні певних подій. 
Основні функції:
* **Автоматизація рутини:** Регулярне резервне копіювання, очищення тимчасових файлів, оновлення системи.
* **Оптимізація ресурсів:** Запуск ресурсомістких завдань у неробочий час (наприклад, вночі).
* **Реакція на події:** Виконання дій при завантаженні системи, вході користувача або зміні стану живлення.

### Порівняння планувальників: Windows Task Scheduler vs Linux Cron

| Характеристика | Windows Task Scheduler | Linux Cron |
| :--- | :--- | :--- |
| **Принцип роботи** | Керується як часом, так і подіями (запуск системи, розблокування, помилки в журналі). | Переважно керується часом (запуск у визначену хвилину, годину, день). |
| **Інтерфейс** | Має потужний графічний інтерфейс (GUI), завдання зберігаються у форматі XML. | Працює через інтерфейс командного рядка (CLI), конфігурація у звичайних текстових файлах. |
| **Гнучкість умов** | Дозволяє задавати складні умови (наприклад, "запускати лише при живленні від мережі"). | Базовий cron виконує завдання безумовно, якщо настав час (складна логіка прописується всередині самого скрипта). |

### Принципи роботи з Cron в ОС Linux
**Cron** — це демон (служба), який працює у фоновому режимі та щохвилини перевіряє таблиці розкладу (`crontab`). 
* **Налаштування:** Кожен користувач в Ubuntu має свій файл розкладу. Для його редагування використовується команда `crontab -e`.
* **Синтаксис:** Файл складається з рядків, де перші 5 полів позначають час, а далі йде команда:
    `[хвилини] [години] [день_місяця] [місяць] [день_тижня] /шлях/до/команди`

**Альтернативи Cron в Linux:**
1.  **systemd timers:** Сучасний стандарт для дистрибутивів на базі systemd (включаючи Ubuntu). Дозволяє відстежувати залежності служб, має мілісекундну точність та вбудоване логування.
2.  **Anacron:** Призначений для систем, які не працюють цілодобово (наприклад, ноутбуки). Якщо система була вимкнена під час запланованого завдання, Anacron виконає його після увімкнення.
3.  **at:** Використовується для одноразового виконання команди у вказаний час (без повторень).

## 2. Планування задач через Cron (ОС Ubuntu)

Для демонстрації створимо директорію для логів та бекапів, з якою працюватимуть наші скрипти.

```bash
mkdir -p ~/scripts ~/backups ~/logs
```

Відкриваємо планувальник командою:
```bash
crontab -e
```

### 2.1. Виконання задачі в чітко визначений час
**Задача:** Щоденне резервне копіювання конфігураційних файлів о 08:30 ранку.
```bash
30 8 * * * tar -czf /home/user/backups/etc_backup_$(date +\%F).tar.gz /etc 2>/dev/null
```
*[Місце для скріншота: вікно терміналу з відкритим crontab та збереженим правилом, а також результат створення архіву о 8:30]*

### 2.2. Виконання задачі двічі в день
**Задача:** Очистка тимчасових каталогів (наприклад, `/tmp/custom_temp`) о 09:00 та 18:30.
```bash
0 9,18 * * * rm -rf /tmp/custom_temp/*
30 18 * * * rm -rf /tmp/custom_temp/*
```
*(Примітка: для 18:30 потрібно виділити окремий рядок, оскільки хвилини відрізняються)*
*[Місце для скріншота: лістинг crontab та перевірка порожнього каталогу /tmp/custom_temp після спрацювання]*

### 2.3. Виконання задачі тільки в будні у визначений проміжок
**Задача:** Запис інформації про завантаженість системи (uptime) щогодини з 08:00 до 18:00 тільки з понеділка по п'ятницю.
```bash
0 8-18 * * 1-5 uptime >> /home/user/logs/work_uptime.log
```
*[Місце для скріншота: вивід файлу work_uptime.log з погодинними записами в робочий час]*

### 2.4. Використання спеціальних макросів (раз у рік, місяць, день, годину, при вмиканні)
**Задача:** Різні системні задачі з використанням вбудованих псевдонімів Cron.
```bash
@yearly echo "З новим роком! Час архівувати старі проєкти" >> ~/logs/yearly.log
@monthly /home/user/scripts/monthly_report.sh
@daily apt-get update > ~/logs/daily_update.log
@hourly sync
@reboot echo "Віртуальна машина запущена: $(date)" >> ~/logs/startup.log
```
*[Місце для скріншота: лістинг crontab зі спеціальними символами @ та лог-файл startup.log після перезавантаження VM]*

## 3. Альтернативний планувальник: systemd timers

У якості сучасної альтернативи Cron на Ubuntu використовується `systemd timers`. Цей метод вимагає створення двох файлів: `.service` (опис того, що робити) та `.timer` (опис того, коли робити).

Створимо таймери для демонстрації дій із завдання 2. Файли створюються в `/etc/systemd/system/`.

### Створення служби (на прикладі бекапу)
Файл `/etc/systemd/system/mybackup.service`:
```ini
[Unit]
Description=Daily Backup Service

[Service]
Type=oneshot
ExecStart=/bin/tar -czf /home/user/backups/etc_backup.tar.gz /etc
```

### Налаштування розкладу (Timer)
Файл `/etc/systemd/system/mybackup.timer`:

Для реалізації завдань з п.2 використовується параметр `OnCalendar=`:

**1. У чітко визначений час (08:30):**
```ini
[Timer]
OnCalendar=*-*-* 08:30:00
Persistent=true
```

**2. Двічі в день (09:00 та 18:30):**
```ini
[Timer]
OnCalendar=*-*-* 09:00:00
OnCalendar=*-*-* 18:30:00
```

**3. У будні з 8 до 18 щогодини:**
```ini
[Timer]
OnCalendar=Mon..Fri *-*-* 08..18:00:00
```

**4. При вмиканні машини (замість @reboot):**
```ini
[Timer]
OnBootSec=1min
```

### Активація та демонстрація
Щоб застосувати таймери:
```bash
sudo systemctl daemon-reload
sudo systemctl enable --now mybackup.timer
sudo systemctl list-timers --all
```
*[Місце для скріншота: вивід команди systemctl list-timers, де видно наші нові таймери, їх статус та час наступного запуску]*

## Висновки / Conclusions

**Висновки:** В ході виконання роботи було досліджено механізми планування завдань в операційних системах. Встановлено, що хоча Windows Task Scheduler надає ширші можливості відслідковування системних подій через зручний графічний інтерфейс, Linux-утиліта Cron є надзвичайно надійним і гнучким інструментом для виконання задач за розкладом на серверах. Практичне застосування Cron дозволило успішно налаштувати періодичне виконання команд у різні проміжки часу: конкретні години, робочі дні та при завантаженні системи. Також було розглянуто `systemd timers` як більш сучасну, безпечну та логічну альтернативу стандартному Cron в середовищі Ubuntu, що дозволяє детальніше контролювати стан виконання фонових процесів.

**Conclusions:** During the practical work, task scheduling mechanisms in operating systems were investigated. It was established that while Windows Task Scheduler provides broader event-tracking capabilities through a user-friendly GUI, the Linux Cron utility is an extremely reliable and flexible tool for executing scheduled tasks on servers. The practical application of Cron allowed for the successful configuration of periodic command execution at various time intervals: specific hours, workdays, and upon system boot. Furthermore, `systemd timers` were examined as a more modern, secure, and logical alternative to standard Cron in the Ubuntu environment, offering granular control over the execution state of background processes.
